## Erros encontrados e tratamento

### 1. Sandbox bloqueou comandos do Windows

**Erro:** o ambiente do agente recusou comandos PowerShell/Git por exigir
acesso à rede local do Windows.

**Impacto:** não foi possível criar a branch, instalar automaticamente os
artefatos, executar alguns scripts administrativos ou iniciar ferramentas que
dependem do listener local.

**Tratamento:** os comandos foram fornecidos para execução no terminal local.
Nenhum dado foi removido por causa desse bloqueio.

### 2. Git não pôde criar/publicar a branch automaticamente

**Erro:** o Git e o GitKraken foram bloqueados pelo sandbox.

**Tratamento:** o repositório foi inicializado/publicado manualmente pelo
usuário na branch `main`, e depois foi criada a branch `azure-cloud-pilot`.

### 3. Editor Vim apareceu durante o merge da licença

**Erro:** ao incorporar a licença criada no GitHub, o Git abriu o Vim para a
mensagem do commit de merge.

**Tratamento:** foi orientado usar `Esc`, `:wq` e `Enter` para salvar a mensagem
e concluir o merge.

### 4. Assinatura Azure rejeitada pelas ferramentas de infraestrutura

**Erro:** o VS Code mostrou a assinatura, mas as consultas de região, SKU e
quota retornaram que o ID era inválido ou inacessível:

```text
5da250f6-41bb-47db-bdda-7df7ad2fb10c
```

**Impacto:** não foi possível validar quotas, gerar infraestrutura Bicep
definitiva ou criar recursos Azure.

**Tratamento:** o bloqueio foi registrado em `.azure/deployment-plan.md`.
Nenhum recurso Azure foi criado.

### 5. Workflow oficial de validação Azure bloqueado

**Erro:** o script PowerShell do workflow `azure-validate` não conseguiu
inicializar por causa da política de sandbox/rede local.

**Impacto:** o plano não pôde ser marcado como `Validated`.

**Tratamento:** o plano permanece explicitamente como bloqueado/não validado.

### 6. Infraestrutura Azure ainda inexistente

**Erro:** não havia arquivos Bicep, Terraform ou `azure.yaml`.

**Impacto:** a arquitetura foi documentada, mas ainda não é provisionável de
forma reproduzível.

**Tratamento:** foram criados o `Dockerfile`, `.dockerignore`, documentação e
o plano de implantação. A geração de Bicep ficou pendente da validação da
assinatura.

### 7. Banco piloto vazio sem inicialização

**Erro:** a API não cria automaticamente schema, unidade, usuário ou
permissões em um PostgreSQL vazio.

**Impacto:** um banco Azure recém-criado não conseguiria iniciar a operação.

**Tratamento:** foi criado `scripts/bootstrap_azure.py`, que prepara a unidade,
o administrador, a função e as permissões de forma idempotente. O script ainda
precisa ser executado contra um banco Azure real depois do provisionamento.

### 8. Hostname Azure incompatível com o QR Code

**Erro:** a API aceitava apenas endereços HTTPS com IP numérico e porta.

**Impacto:** um hostname DNS do Azure Container Apps seria descartado e o QR
Code não funcionaria.

**Tratamento:** `SetupController` passou a validar hostnames DNS HTTPS, sem
permitir usuário, query string, fragmento ou portas diferentes de 443.

### 9. APK compilado com hostname Azure provisório

**Erro:** alguns APKs foram gerados com:

```text
https://bar-api.example.azurecontainerapps.io
```

Esse endereço era apenas um placeholder e não existia.

**Impacto:** o APK mostrava que não conseguia falar com o computador do bar.

**Tratamento:** os APKs foram recompilados com:

```text
Operação: https://192.168.0.8:8443
Treinamento: https://192.168.0.8:18443
```

Também foi adicionada uma recuperação automática que descarta o hostname
provisório salvo no aparelho e retorna ao endereço local padrão.

### 10. APK não conectava quando o IP local era diferente

**Erro:** o endereço padrão depende do IP local do computador.

**Impacto:** se o roteador atribuir outro IP, o APK não encontra a API.

**Tratamento:** foi orientado usar o botão **Conexão** e informar o endereço
HTTPS exibido em **Configurações → Acesso pelo Android**. O IP `192.168.0.8`
não deve ser tratado como permanente.

### 11. Tela branca no programa Windows

**Erro:** o programa Windows foi aberto diretamente sem iniciar a API Java.

**Sintoma:** janela aberta com área branca e a mensagem:

```text
Serviço indisponível. Execute Iniciar Bar e clique em Reconectar.
```

**Causa:** o executável é apenas o cliente JavaFX/WebView. Ele depende da API,
que depende do PostgreSQL.

**Tratamento:** iniciar Docker, executar `Iniciar Bar na Rede.cmd` ou
`Iniciar Treinamento.cmd`, e só depois abrir/reconectar o programa.

### 12. Confusão entre operação e treinamento

**Erro:** foi considerado que o modo Bar na Rede poderia conflitar com o
treinamento.

**Esclarecimento:** os modos usam portas e bancos separados:

```text
Operação: 8443
Treinamento: 18443
```

**Tratamento:** manter ambos os modos. Para testar somente treinamento, parar o
serviço e executar apenas `Iniciar Treinamento.cmd`.

### 13. Testes Java executados com Java 21

**Erro:**

```text
UnsupportedClassVersionError:
class file version 69.0; runtime recognizes up to 65.0
```

**Causa:** as classes foram compiladas com Java 25, mas o executor de testes
usou Java 21.

**Tratamento:** configurar `JAVA_HOME` para o Temurin 25 do projeto antes de
executar Maven.

### 14. Maven executado sem JDK 25

**Erro:**

```text
release version 25 not supported
```

**Causa:** o terminal estava usando um JDK anterior ao Java 25.

**Tratamento:** usar:

```powershell
$env:JAVA_HOME='C:\Users\User\AppData\Local\Programs\BarDev\jdk-25.0.4.1+1'
$env:Path="$env:JAVA_HOME\bin;$env:Path"
```

### 15. Política de execução do PowerShell

**Erro:**

```text
scripts\ambiente.ps1 não pode ser carregado porque a execução de scripts foi desabilitada
```

**Tratamento:** usar uma sessão temporária permitida:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

ou executar o script com:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ...
```

### 16. Caminho incorreto do ambiente Python

**Erro:** foi digitado:

```text
..venv\Scripts\python.exe
```

**Causa:** faltou a barra invertida entre o ponto e `.venv`.

**Caminho correto:**

```text
.\.venv\Scripts\python.exe
```

### 17. Comandos PowerShell com aspas/operadores incorretos

**Erro:** alguns comandos compostos usando `&&`, aspas escapadas ou chamadas
aninhadas falharam no Windows PowerShell.

**Tratamento:** os comandos foram divididos em etapas e executados com
PowerShell nativo, usando `;`, variáveis de ambiente e o operador `&` fora de
strings.

### 18. Primeiro empacotamento do programa Windows falhou nos testes

**Erro:** o empacotamento pelo script completo falhou porque o Maven tentou
executar testes que não conseguiam conectar ao PostgreSQL local.

**Tratamento:** o pacote Windows foi recompilado com `-DskipTests` depois que a
compilação dos fontes foi confirmada. O artefato foi gerado com sucesso.

### 19. Teste da API sem PostgreSQL

**Erro:** a suíte iniciou, mas falhou ao criar o contexto Spring por não haver
banco PostgreSQL de teste disponível.

**Impacto:** os testes funcionais completos não foram aprovados neste ambiente.

**Tratamento:** a compilação e o `test-compile` passaram. Para validar
funcionalmente, iniciar Docker e executar o fluxo de banco descartável do
projeto.

### 20. APK e programa não atualizavam automaticamente

**Erro:** os artefatos foram gerados na pasta `output`, mas a instalação
existente no celular e os atalhos do Windows continuaram apontando para versões
anteriores.

**Tratamento:** instalar manualmente os APKs novos e recriar os atalhos com
`Criar Atalhos.cmd`. O programa Windows é portátil e não possui instalador MSI.

## Procedimento local recomendado

1. Ligue o Docker Desktop.
2. Execute `Parar Bar.cmd` se houver um serviço antigo.
3. Para operação local, execute `Iniciar Bar na Rede.cmd`.
4. Para treinamento, execute `Iniciar Treinamento.cmd`.
5. Abra o programa Windows depois que a API estiver ativa.
6. No APK, use **Conexão** e informe o endereço HTTPS exibido em
   **Configurações → Acesso pelo Android**.
7. Se o firewall bloquear as portas, execute `Configurar Rede do Bar.cmd`
   como Administrador.

## Instalação dos artefatos

### Windows

Execute:

```text
E:\Bar\output\app\Bar do Zico\Bar do Zico.exe
```

Se os atalhos ainda apontarem para uma versão antiga, execute:

```text
E:\Bar\Criar Atalhos.cmd
```

### Android

Instale no celular o APK correspondente:

```text
E:\Bar\output\android\Bar-do-Zico.apk
E:\Bar\output\android\Bar-do-Zico-Treinamento.apk
```

Se o Android não aceitar a atualização por cima, desinstale a versão antiga e
instale o APK novo. A desinstalação pode remover configurações locais do
aplicativo, mas não remove os dados do PostgreSQL no computador.
